# Руководство по внесению вклада (Contributing Guide)

[English version](CONTRIBUTING.md)

Мы рады, что вы хотите внести свой вклад в разработку Yandex Messenger Native! Этот проект написан на Rust с использованием GTK4 и Libadwaita. Ниже описаны основные правила и рекомендации для разработчиков.

Если меняется пользовательское поведение, обновляйте документацию **на обоих языках** (`README.md` / `README.ru.md`, `CHANGELOG.md` / `CHANGELOG.ru.md` и любую другую затронутую пару).

## Требования к окружению

Для сборки и тестирования проекта вам понадобятся:
- **Rust Toolchain**: Установите стабильную версию Rust через [rustup](https://rustup.rs/).
- **GTK4 и Libadwaita**: Системные библиотеки для разработки. В Ubuntu/Debian их можно установить командой:
  ```bash
  sudo apt install -y libgtk-4-dev libadwaita-1-dev pkg-config
  ```
- Дополнительно (для записи голоса): `libgstreamer1.0-dev`, `libgstreamer-plugins-base1.0-dev`.

## Процесс разработки

### 1. Подготовка
Форкните репозиторий и клонируйте его локально:
```bash
git clone https://github.com/your-username/yandex-messenger-native.git
cd yandex-messenger-native
```

### 2. Сборка и запуск
Вы можете использовать стандартные команды cargo или Makefile:
```bash
make build  # Сборка проекта
make run    # Запуск приложения
```

### 3. Проверка качества кода
Перед отправкой изменений обязательно убедитесь, что код проходит все проверки:
- **Форматирование**:
  ```bash
  cargo fmt --check
  ```
- **Статический анализ (Linter)**:
  ```bash
  cargo clippy -- -D warnings
  ```
- **Тесты**:
  ```bash
  cargo test
  ```

## Правила оформления изменений

### Ветвление
- Создавайте отдельные ветки для каждой фичи или багфикса:
  ```bash
  git checkout -b feature/your-feature-name
  # или
  git checkout -b fix/bug-description
  ```

### Коммиты
- Пишите понятные сообщения коммитов на английском или русском языке.
- Избегайте коммитов с неинформативными названиями (например, "fix", "update").

### Создание Pull Request
1. Убедитесь, что ваша ветка синхронизирована с `main`.
2. Направьте Pull Request в ветку `main` оригинального репозитория.
3. Опишите внесенные изменения в описании PR, укажите, какие проблемы они решают.
4. Дождитесь прохождения проверок CI и ревью кода.
