# Отчет по реверс-инжинирингу Yandex Messenger (Telemost)

## Цель
Провести анализ APK-файла `ru.yandex.telemost` для подготовки кодовой базы к созданию форка с восстановлением и возможным расширением функционала.

## Результаты распаковки и декомпиляции
Были выполнены два типа декомпиляции:
1. **Декомпиляция в Java/Kotlin (jadx)**: Исходный код извлечен в директорию `decompile_out`. Это позволяет анализировать логику работы приложения, алгоритмы, бизнес-логику и работу с API.
2. **Дизассемблирование в Smali (apktool)**: Ресурсы и байткод извлечены в директорию `apktool_out`. Это формат, который позволяет вносить изменения в код (модифицировать smali) и пересобирать APK-файл.

## Основные API-эндпоинты
Приложение взаимодействует со следующими основными сервисами Яндекса:
- `https://api.messenger.yandex.net` — Основное API мессенджера
- `https://backend.messenger.yandex.net` — Бэкенд
- `https://push.yandex.ru` — Push-уведомления
- `https://telemost.yandex.ru` — Видеозвонки (Телемост)
- `https://mobapi.calendar.yandex.ru` — Интеграция с календарем
- `https://mobileproxy.passport.yandex.net` — Аутентификация (Яндекс ID)

## Структура приложения
- **Пакет**: `ru.yandex.telemost`
- **Application Class**: `com.yandex.messenger.MainApplication`
- **Основная Activity**: `com.yandex.messenger.LauncherActivity` / `com.yandex.messaging.activity.MessengerActivity`
- Приложение имеет сложную модульную структуру (com.yandex.messaging, com.yandex.passport и др.) и активно использует кодогенерацию/обфускацию (R8/ProGuard).

## Дальнейшие шаги по созданию форка

Поскольку полноценная компиляция из декомпилированного Java-кода (jadx) невозможна из-за сильной обфускации и отсутствия проприетарных библиотек в исходном виде, разработка форка осуществляется путем патчинга Smali-кода.

### 1. Внесение изменений
Вы можете находить нужный функционал в папке `decompile_out/sources/` (написанный на Java/Kotlin), а затем вносить соответствующие изменения в файлы `.smali` внутри папки `apktool_out/smali*/`.

### 2. Сборка модифицированного APK
Для пересборки приложения используйте скрипт `build_fork.sh`, который был создан в корне проекта. Он использует `apktool` для сборки и `apksigner` для подписи APK-файла.

### 3. Подпись APK
Для установки на устройства Android новый APK должен быть подписан. Был сгенерирован тестовый ключ (`fork_keystore.jks`), который используется в скрипте сборки.

## Возможные векторы для восстановления/изменения функционала:
1. **Перенаправление API**: Замена базовых URL (например, `api.messenger.yandex.net`) на ваши собственные серверы в коде Smali, если вы планируете развернуть собственный бэкенд.
2. **Отключение аналитики и метрик**: Удаление вызовов AppMetrica и других трекеров для повышения приватности.
3. **Обход сертификатного пиннинга (SSL Pinning)**: Приложение, вероятно, использует Network Security Config или OkHttp CertificatePinner. В `network_security_config.xml` (в `apktool_out/res/xml/`) можно добавить доверие к пользовательским сертификатам для перехвата трафика и детального анализа API.
